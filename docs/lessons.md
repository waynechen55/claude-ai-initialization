# Lessons: what was recorded versus what was proved

Every serious bug found in this project has been the same bug wearing a
different hat: **what got recorded was not what got proved** — a claim that
outran its evidence. Each row is a real failure, found while verifying the
program against real infrastructure, with the general rule adopted for its
whole class. The habits that follow from them are in
[CONTRIBUTING.md](../CONTRIBUTING.md#the-mistake-this-codebase-keeps-making);
the release-by-release story is in [history.md](history.md).

Host names are neutral examples; the failures were real.

| What was recorded | What had actually been proved |

| build.opensuse.org: "the login is recognised, and the service has no account behind it" -- every logged-in call an HTML 404, no login and a made-up one 401 | the account existed: osc with the same login answered `whoami`, and the same calls with `Accept: */*` returned the data. The bridge's weighted `Accept: application/xml, text/xml;q=0.9, */*;q=0.1` made the gateway answer with its web page; the run that wrote it held no credential, so it only ever saw 401. **A web page proves nothing about the credential or the account: the request's form is tried first** (`request_forms`), a bridge sends one Accept value and retries a read-only call once with `*/*`, and a 404 is "no account" only in the API's own form. **Before blaming a login, vary the request with the same login, and compare with the product's own client** |
